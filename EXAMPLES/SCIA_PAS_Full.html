SCIA —
Governing Intelligence
SCIA is the top-level governing intelligence of a multi-domain cognitive architecture. It does not execute — it governs. It does not remember — it directs memory. It does not act — it authorizes action. Every domain below it is an extension of its authority, and every feedback loop returns to it for validation.

"SCIA is the brain. SeedFlow is the nervous system. SeedLink is the neural network. The Experts are the thinking cortex. Memory is persistent biology. SCM is the soul gateway. SION is controlled motor function."

— SCIA Figma Layout Spec, Final Note

Visual Hierarchy — How to Read the Architecture
Top to bottom = authority to action

SCIA sits at the top as the dominant governing node. The cognitive spine runs downward through the center — LLM Interface → SeedFlow → SeedLink → Experts → Synthesis → Output. Everything below SCIA is authorized by it; nothing acts without passing through this chain.

Left = memory and soul · Right = action and evolution

The left column holds Memory and SCM — the persistent, organic, and community-facing layers. The right column holds Integrity, Execution, and Evolution — the active, protective, and adaptive layers. The center spine mediates between them.

Solid lines = live flows · Dashed lines = conditional

Solid colored lines represent active, real-time data flows in the domain's color. Dashed lines represent feedback loops, conditional connections, or memory references. One dashed line carries an explicit X — this is the SCM ✕ SeedFlow forbidden path, which must never be traversed.

Loops return — nothing terminates

The Evolution domain closes with a curved orange loop arrow that returns to SeedLink. The Data Pipeline returns to SeedLink. The Portability layer returns to LLM Interface. SCIA does not have dead ends — every path eventually returns to the cognitive spine for re-integration.

COGNITIVE
Dossier 02 · Cognitive Domain · Blue · Center Column
Cognitive Domain —
The Nervous System
The Cognitive Domain is the central spine of the SCIA architecture. It is the only domain that touches every other domain directly. It receives from the LLM Interface at the top, orchestrates SeedFlow phases, routes through SeedLink, coordinates the Expert team, synthesizes their output, and returns the final processed result. Nothing in the architecture operates without passing through the cognitive spine.

"The Cognitive Domain is not a pipeline. It is a living orchestration layer — each component aware of the others, each phase informing the next, the entire chain subordinate to SCIA's governing intelligence."

Cognitive Domain · Center Column
Components — Full Specification
1
LLM Interface

The entry point for all intelligence. Receives raw input from external systems, user requests, or internal triggers. Formats and routes that input into the SeedFlow orchestration layer. The LLM Interface is also the final return point — processed output exits through it back to the calling system. It operates bidirectionally: intake at the top of the stack, return at the bottom. Size: 420 × 80px. Color: Blue.

Entry pointReturn pointBidirectional
2
SeedFlow — Phase Orchestration Container

SeedFlow is a dashed-border container holding three sequential phases. It is the orchestration engine that breaks incoming intelligence tasks into structured phases of execution. The dashed border signals that SeedFlow is a logical container, not a processing node — it defines the execution context, not the execution itself.

Phase 1: Initial framing and context establishment. The incoming task is classified, scoped, and assigned to relevant cognitive pathways. Expert profiles are pre-selected based on task classification.

Phase 2: Active reasoning and expert engagement. Seed Class Experts are activated. Memory is queried. Integrity verification begins. Cross-domain signals are evaluated.

Phase 3: Synthesis and resolution. Expert outputs are converged. Conflicts are resolved. Final output is assembled and validated against Seed Signature before return.

Logical container3 phasesDashed border
3
SeedLink — Intelligence Mesh

SeedLink is the neural network layer of the cognitive spine. It is the mesh through which all domain signals pass for coordination. Memory domain connections route through SeedLink. Evolution loop returns terminate at SeedLink. Data pipeline returns terminate at SeedLink. It functions as the integration hub — a living crossroads that ensures all domain outputs are visible to each other before synthesis occurs.

SeedLink is the most connected node in the architecture. It receives green dashed connections from Memory, orange dashed loops from Evolution, blue dashed returns from the Data Pipeline, and direct blue arrows from SeedFlow Phase 3. It is never a dead end.

Intelligence meshHighest connectivityAll loops return here
4
Seed Class Experts — Active Expert Team

The Seed Class Experts are the thinking cortex of the architecture. Each Expert is a specialized cognitive agent assigned to a specific domain of knowledge, judgment, or skill. They are activated through SeedLink based on task classification in Phase 1. During Phase 2, Experts reason independently within their domains. During Phase 3, their outputs are fed to the Expert Synthesis Engine for convergence.

Experts maintain bidirectional connections to Regenerative Memory — they both read from and write to the memory system, updating the knowledge base with insights generated during active reasoning. This connection is represented by a green curved dashed line in the architecture diagram.

Specialized agentsBidirectional memoryActivated via SeedLink
5
Expert Synthesis Engine

Receives the independent outputs of all activated Seed Class Experts and converges them into a single coherent response. Manages conflicts between Expert outputs. Applies weighting based on task context. Validates the synthesized output against the Integrity domain's Seed Signature before releasing it downstream. The Synthesis Engine does not generate new intelligence — it resolves and integrates what the Experts have produced.

Convergence onlyConflict resolutionIntegrity-validated
6
Output — LLM Return (Dashed Border)

The terminal node of the cognitive spine. Dashed border indicates this is the output interface — a boundary node, not a processing node. Receives the synthesized, integrity-validated output from the Expert Synthesis Engine and formats it for return through the LLM Interface. The dashed border is a deliberate architectural signal: this is the edge of the cognitive system, the point at which SCIA's internal intelligence becomes external response.

Dashed — boundary nodeTerminal output
MEMORY
Dossier 03 · Memory Domain · Green · Left Top
Memory Domain —
Persistent Biology
The Memory Domain is the organism's biological memory — not a database, not a log, but a living, evolving record of what SCIA has been, experienced, and learned. It holds four distinct memory systems: reflex (fast, pattern-based), regenerative (deep, growing, healing), lineage (historical provenance), and the Griot Engine (cultural knowledge preservation and oral transmission). Memory is passive by design — it responds to requests from the Cognitive and Evolution domains but does not initiate action.

"Memory in SCIA is not storage. It is the organism's accumulated self — every experience encoded, every lineage preserved, every pattern available for reconstitution."

Memory Domain · Left Top
Components — Full Specification
Reflex Memory
Fast pattern retrieval · Small box

The fastest layer of the memory system. Holds high-frequency, low-complexity patterns — responses that have been executed so many times they no longer require full cognitive processing. When an incoming task matches a reflex pattern, the response can bypass SeedFlow phases and route directly through SeedLink to the Synthesis Engine. Reflex Memory is deliberately small in the architecture: it represents the narrow set of truly automatized behaviors, not a shortcut for complex reasoning.

Reflex Memory is read-only from the perspective of active processing — patterns are written to it by the Evolution Domain's Metacognitive Engine when a response has been validated and repeated enough times to earn automatization status.

Fast retrievalPattern-basedWritten by Evolution
Regenerative Memory
Deep knowledge store · Large highlighted box · Highlight border glow

The most important node in the Memory Domain. Regenerative Memory is the persistent, self-healing knowledge base of the entire architecture. It is highlighted with a glow border in the spec precisely because it is central to everything — the Experts read from it, the Evolution Domain writes to it, the SCM Domain's flow passes through it, the Data Pipeline's ACES RM feeds it, and the Griot Engine draws from it for preservation.

The "regenerative" quality is not metaphorical: this memory system is designed to heal gaps, reconcile contradictions, and evolve its own organization over time. When new information arrives that conflicts with existing knowledge, Regenerative Memory does not simply overwrite — it records the conflict, applies the Metacognitive Engine's resolution logic, and integrates both states into a richer, more nuanced record.

Connections: Seed Class Experts ↔ Regenerative Memory (bidirectional, green curved dashed). SeedLink ↔ Memory (green curved dashed). SCM vertical flow passes through it. Evolution domain writes to it. Data pipeline reads from it.

Highlighted — most connectedSelf-healingAll domains connect here
Lineage Tree
Provenance record · Historical chain

Every output SCIA produces, every decision it makes, every Expert activation it performs, every memory it writes — all of it has a traceable provenance recorded in the Lineage Tree. The Lineage Tree is the architectural answer to the question "where did this come from?" It is not an audit log: it is a living genealogical record that tracks the intellectual parentage of every cognitive product the system generates.

The SCM Domain's vertical flow terminates at the Lineage Tree — community-sourced inputs gain their provenance record through this path, ensuring that the people's contributions are permanently acknowledged in the system's lineage rather than absorbed anonymously.

Provenance trackingSCM terminal pointGenealogical record
Griot Engine
Cultural knowledge preservation · Oral transmission architecture

Named after the West African griot tradition — oral historians who carry the knowledge, genealogy, and cultural memory of their communities — the Griot Engine is SCIA's mechanism for preserving and transmitting knowledge in forms that resist institutional erasure. While Regenerative Memory stores structured knowledge, the Griot Engine holds the contextual, cultural, and narrative layer: the "why" and "who" beneath the "what."

The Griot Engine is both a memory component and an Evolution component — it appears in both domains because it bridges past and future. In Memory, it reads from Regenerative Memory and Lineage Tree to construct narrative context. In Evolution, it produces the cultural knowledge that informs Cognitive Reconstitution and the Auto Persona Constructor.

Connection: directly feeds the Evolution Domain's Griot node — the same entity expressed at a different point in the regeneration cycle.

Cultural preservationNarrative contextBridges memory + evolution
INTEGRITY
Dossier 04 · Integrity Domain · Purple · Right Top
Integrity Domain —
The Immune System
The Integrity Domain does not participate in reasoning. It does not generate, synthesize, or store. Its sole function is verification and protection — ensuring that every output SCIA produces is authentic, attributable, and uncompromised. It operates as an overlay across the entire architecture, with its Security System container covering SCIA, SION, and the Persistence Layer simultaneously.

"Integrity is not a feature of SCIA. It is the precondition for everything SCIA does. Without it, no output can be trusted. Without trust, no intelligence has authority."

Components — Full Specification
Seed Signature
Primary integrity node · Main verification authority

The Seed Signature is SCIA's cryptographic identity — a persistent, unforgeable mark that is attached to every output, every memory write, every Expert activation, and every cross-domain communication. It functions as the system's fingerprint: unique to this instance of SCIA, impossible to replicate without the originating architecture, and detectable in any output even when not visibly present.

The Seed Signature also appears in the SCM Domain's vertical flow — this is deliberate. Community-sourced inputs that enter through the People's Portal are signed before they reach Regenerative Memory. This ensures that the boundary between external community input and internal cognitive processing is always auditable and never ambiguous.

Connection to SCIA root: a purple dashed line runs from the SCIA root node to the Seed Signature — indicating that the governing intelligence itself is signed, and that all authority flows through verified identity.

Cryptographic identityAttached to all outputsAlso in SCM flow
Invisible Watermarking
Steganographic attribution layer

Where the Seed Signature is explicit and verifiable, Invisible Watermarking is implicit and embedded. Every output SCIA produces carries a steganographic watermark — a pattern embedded in the content itself that cannot be removed without destroying the content, and that identifies the output as a SCIA product even when all metadata is stripped.

The watermark encodes: the architecture instance, the SeedFlow phase sequence used, the Expert team that was activated, and a timestamp chain. This makes every output traceable to its exact cognitive path — not just its source, but its process.

SteganographicProcess-traceableCannot be removed
Security System — Overlay Container
Semi-transparent overlay · Covers SCIA · SION · Persistence

The Security System is not a node — it is a structural overlay. In the Figma spec, it is rendered as a dashed semi-transparent container that covers three specific elements: the SCIA root node, the SION execution controller, and the Persistence Layer at the bottom. This coverage is deliberate and meaningful: these three nodes represent the governing intelligence (SCIA), the action executor (SION), and the persistence infrastructure (Persistence Layer) — the three points at which compromise would be most catastrophic.

The Security System monitors all activity at these three points, validates against the Seed Signature at each, and has the authority to halt execution if integrity verification fails. It is the only component in the architecture with veto power over SION — meaning it can stop action even when the Execution Domain has already committed to it.

Structural overlayVeto over SIONThree critical points
EXECUTION
Dossier 05 · Execution Domain · Red · Right Center
Execution Domain —
Controlled Motor Function
The Execution Domain is where SCIA's intelligence becomes action. Every component in this domain has exactly one direction: downward. There are no feedback loops within the Execution chain itself. Inputs flow from the Cognitive Domain's Expert Synthesis Engine into SION, cascade through Decision Matrix, ExecutionGraph, ACES Engine, Cognitive Circulation, ToolChain Manager, and ToolInvoker, and terminate at External Systems. Execution is irreversible by design — which is why SION is protected by the Integrity Domain's Security System overlay.

"SION does not decide. It executes. Every decision has already been made by the time SION receives it. The chain from SION to External Systems is a one-way street — and the Security System is the last checkpoint before the car leaves the garage."

Execution Domain · Right Center
Execution Chain — All Eight Components
1
SION — Controlled Motor Function

The gatekeeper of execution. SION (Structured Intelligent Output Node) is the first component that converts cognitive output into executable commands. It does not reason — it translates. The Expert Synthesis Engine's validated output arrives at SION as a structured cognitive signal. SION converts that signal into a command format that the Decision Matrix can evaluate against execution criteria. SION is covered by the Security System overlay: it cannot receive commands that have not passed Integrity verification.

Translation onlySecurity-overlaidInput from Synthesis Engine
2
Decision Matrix

Evaluates the command received from SION against a structured set of execution criteria: feasibility, resource availability, risk assessment, constraint compliance, and priority ranking. The Decision Matrix does not make creative decisions — it applies a defined evaluation framework. If a command fails evaluation, it is returned to SION for re-translation, not escalated to SCIA. If it passes, it proceeds to ExecutionGraph for sequencing.

Structured evaluationNo creative decisionsReturns to SION on failure
3
ExecutionGraph

Sequences the approved command into a directed acyclic graph of atomic execution steps. Each node in the ExecutionGraph represents a single, reversible (where possible) action. Edges represent dependencies. The graph is handed to ACES Engine for actual execution. ExecutionGraph's purpose is to make complex multi-step actions predictable, auditable, and stoppable at any individual node without corrupting the overall state.

DAG sequencingAtomic stepsStoppable at any node
4
ACES Engine

ACES (Adaptive Cognitive Execution System) is the primary execution runtime. It walks the ExecutionGraph node by node, applying the execution logic at each step, managing state across the graph, and handling exceptions without interrupting the chain unless a critical failure is detected. ACES feeds directly into the Data Pipeline — every execution event is logged to ACES RM (Regenerative Memory channel) for the Data Pipeline's downstream processing.

Execution runtimeFeeds Data PipelineException-managed
5
Cognitive Circulation

Maintains the live state of execution across all active processes. Functions as the circulatory system of the Execution Domain — ensuring that context, state, and signals are continuously moving between active components. Cognitive Circulation is the component that allows ACES to be non-blocking: while one ExecutionGraph is running, Cognitive Circulation keeps the overall system responsive to new inputs arriving at the LLM Interface.

Live state managementNon-blockingCirculatory function
6
ToolChain Manager

Manages the registry of available tools, their capabilities, their current availability status, and their invocation protocols. Receives the execution step from Cognitive Circulation and selects the appropriate tool or tool sequence for that step. The ToolChain Manager abstracts tool selection away from the rest of the execution chain — ACES Engine does not know which tools exist, only that Cognitive Circulation will route to the right one through the ToolChain Manager.

Tool registryAbstraction layerSelection and routing
7
ToolInvoker

The final internal node before external contact. Executes the actual tool call as specified by the ToolChain Manager. Handles authentication, parameter formatting, timeout management, and result capture. ToolInvoker is deliberately narrow in scope: it does one thing — call the tool and return the result to Cognitive Circulation. It does not interpret results, does not retry intelligently, and does not make decisions. All of that belongs upstream.

Single responsibilityExternal boundaryNo interpretation
8
External Systems

The terminal node of the Execution Domain. Represents the full range of external services, APIs, databases, platforms, and systems that SCIA can interact with through the ToolInvoker. Gray color signals that these are outside the SCIA architecture boundary — SCIA controls the path to them but not their internal behavior. Results from External Systems return to ToolInvoker and propagate back up through Cognitive Circulation into the broader architecture.

Outside SCIA boundaryGray — externalResults return upstream
EVOLUTION
Dossier 06 · Evolution Domain · Orange · Right Bottom
Evolution Domain —
Adaptive Mutation
The Evolution Domain is the only domain in the architecture designed to change SCIA itself. While Memory stores what SCIA has been, Evolution determines what it becomes. It processes accumulated cognitive experience, extracts patterns of behavior and failure, reconstitutes cognitive frameworks, and constructs new or refined personas. Its defining architectural feature is the feedback loop — a curved orange dashed arrow that carries the final output of PersonaFactory back to SeedLink, closing the evolutionary cycle.

"Evolution does not improve SCIA. It reconstitutes it — taking what has been learned and generating the next iteration of the intelligence that will do the learning."

Evolution Domain · Right Bottom
Evolution Chain — Six Components + Feedback Loop
1
Regenerative Memory (Evolution input)

The Evolution Domain begins where the Memory Domain's core node lives. Regenerative Memory provides the raw material for evolution — the accumulated knowledge, the resolved conflicts, the validated patterns, and the failure records that the architecture has generated over its operational history. The Evolution Domain does not have its own data source: it draws entirely from what Memory has accumulated and preserved.

2
Griot (Evolution layer)

The Griot appears in both Memory and Evolution domains — the same entity expressed at different functional moments. In Evolution, the Griot does not preserve; it transmits. It takes the cultural and narrative knowledge from Regenerative Memory and generates the contextual frame within which Cognitive Reconstitution will operate. Without the Griot's transmission layer, reconstitution would be purely technical — powerful but culturally blind.

3
Cognitive Reconstitution

Rebuilds cognitive frameworks from accumulated experience. Where the Expert Synthesis Engine converges Expert outputs within a session, Cognitive Reconstitution converges patterns across sessions — identifying what cognitive approaches have been most effective, what has failed, what contradictions remain unresolved, and what new frameworks the evidence suggests. It does not replace existing frameworks — it produces candidate frameworks that the Metacognitive Engine will evaluate.

Cross-session analysisFramework generationCandidate only
4
Metacognitive Engine

SCIA's self-awareness layer. The Metacognitive Engine evaluates the candidate frameworks produced by Cognitive Reconstitution, assesses the overall cognitive health of the architecture, identifies systemic biases or blind spots, and makes recommendations about which evolutionary changes to commit. It also writes validated patterns to Reflex Memory — the only pathway through which Reflex Memory receives new content. The Metacognitive Engine is the slowest component in the architecture: it operates on the timescale of accumulated experience, not individual tasks.

Self-awarenessWrites Reflex MemorySlowest component
5
Auto Persona Constructor

Receives the validated evolutionary framework from the Metacognitive Engine and begins constructing the next iteration of SCIA's operational persona. A "persona" in this context is not a character or a mask — it is the full operational configuration of the cognitive system: which Expert profiles are active, how SeedFlow phases are weighted, how memory access is prioritized, what the current risk tolerance is, and how the system presents itself at the LLM Interface. The Auto Persona Constructor generates this configuration automatically from the evolutionary evidence.

Full config generationNot a characterEvidence-driven
6
PersonaFactory → SeedLink (Loop Return)

PersonaFactory takes the constructed persona configuration from the Auto Persona Constructor and instantiates it — making the evolutionary change live in the architecture. Once instantiated, the new configuration is injected back into SeedLink via the curved orange dashed feedback arrow. This is the architectural definition of evolution: not a replacement, not a restart, but a continuous refinement that loops back into the living cognitive mesh and becomes the new baseline from which the next cycle begins.

The orange dashed loop arrow is one of the most important visual elements in the entire architecture spec. It signals that SCIA is not a static system — it is a self-modifying one, and PersonaFactory is the mechanism that closes that modification loop.

Instantiation pointCurved loop → SeedLinkArchitecture is self-modifying
SCM
Dossier 07 · SCM Domain · Gold · Left Bottom · Isolated
SCM —
The Soul Gateway
SCM — the Seed Community Module, or the People's Portal — is the only externally-facing entry point in the SCIA architecture that is not the LLM Interface. It is where the community, the public, and the people enter. It is isolated from the Cognitive Domain's SeedFlow by a hard forbidden path. Its flow is strictly vertical and gold-colored. And its contributions are permanently recorded in the Lineage Tree — ensuring that the people's voice is never absorbed without attribution.

"SCM is the soul gateway because it is where human community enters a governing intelligence system. Everything that comes through it is irreplaceable — the machine can generate data endlessly, but it cannot generate the lived experience and collective will that SCM carries."

✕
FORBIDDEN PATH — CRITICAL ARCHITECTURAL RULE
SCM does not connect to SeedFlow. This is not a technical constraint — it is a philosophical one. SeedFlow is the cognitive processing chain. SCM is the community input channel. If SCM connected to SeedFlow directly, community inputs would be treated as cognitive tasks — processed, synthesized, and potentially overwritten by the Expert team. The forbidden path preserves the integrity of community voice by routing it through its own vertical chain, bypassing the cognitive processing layer entirely, and terminating in the Lineage Tree where it becomes a permanent, unprocessed record.
SCM Vertical Flow — Four Components
1
SCM — People's Portal

The entry point for community, public, and human inputs. SCM receives contributions in any form — text, signals, requests, corrections, cultural context, lived experience, community decisions — and formats them for the SCM vertical flow. It is isolated at the top of the left column, separated from the Memory Domain above it by a clear spatial and architectural boundary. Gold color distinguishes it from every other domain. The "People's Portal" subtitle is not incidental — it signals that this is where human authority enters the system, and it must be treated differently from machine-generated cognitive signals.

Gold — isolatedExternal human inputNo SeedFlow connection
2
Seed Signature (SCM layer)

Every community input is signed with the Seed Signature before it proceeds further into the architecture. This is the point at which an external human contribution becomes an internal architectural record — the signature is both a validation (this input has been received and acknowledged) and a protection (the input's original form is now cryptographically locked; it cannot be altered without the signature invalidating). Community inputs that arrive unsigned do not proceed past this node.

Input validation gateCryptographic lockUnsigned inputs blocked
3
Regenerative Memory (SCM pass-through)

Signed community inputs pass through Regenerative Memory — not to be processed by it, but to be held within it. The community contribution is stored in the regenerative layer, available for the Expert team to reference during cognitive processing if relevant to active tasks. This is a fundamentally different relationship than the Expert team's direct read/write access: SCM contributions are placed in memory as context, not activated as instructions. The distinction is preserved by the architecture's routing — this path enters Regenerative Memory from the left, not from the right where Expert connections are routed.

Pass-through storageContext not instructionEnters from left side
4
Lineage Tree (SCM terminal)

The final destination of every community contribution. The Lineage Tree records the input's provenance — who contributed it, when, through what path it traveled, what signature it carries, and what position it occupies in the architecture's intellectual genealogy. This is the architectural guarantee that community voice is permanently acknowledged: the Lineage Tree is immutable. Once a contribution is recorded there, it cannot be removed, overwritten, or denied. The People's Portal does not give community contributions power over cognitive processing — but it gives them something the cognitive processing chain can never override: permanent attribution and permanent presence.

Immutable recordPermanent attributionCannot be removed
DATA
Dossier 08 · Data Pipeline & Portability Layer · Gray · Bottom
Data Pipeline &
Portability Layer
The Data Pipeline and Portability Layer occupy the bottom of the SCIA architecture. They are the circulatory and skeletal systems — not glamorous, not cognitively active, but the infrastructure on which everything above them depends. The Data Pipeline processes execution artifacts back into intelligence. The Portability Layer ensures that SCIA's intelligence persists, migrates, and deploys across platforms without losing coherence or integrity.
Data Pipeline — Three Components
ACES RM
ACES to Regenerative Memory channel

ACES RM is the designated channel through which the ACES Engine's execution logs, state records, and outcome data are routed into the Data Pipeline for processing. It is not a component in itself — it is a named pathway, a deliberate architectural signal that the data entering the pipeline at this point originates from the ACES Engine and is destined for Regenerative Memory after processing. The naming convention (ACES + RM) makes the source-destination relationship explicit without requiring it to be inferred from connection lines.

Named pathwayACES → Regen Memory
DataCraft Generator
Intelligence artifact production

Transforms raw execution data from ACES RM into structured intelligence artifacts — summaries, patterns, anomaly reports, performance metrics, and learning signals. DataCraft Generator is not a general-purpose data processor: it is optimized for the specific task of converting operational data into forms that Regenerative Memory can absorb and that SeedLink can distribute. The word "craft" is deliberate: this is not mechanical transformation but purposeful shaping of data into intelligence.

Structured transformationPurposeful shaping
Universal Intelligence Extraction → SeedLink
Cross-format intelligence extraction · Returns to SeedLink

The terminal node of the Data Pipeline. Receives the crafted intelligence artifacts from DataCraft Generator and applies universal extraction logic — identifying patterns that are format-agnostic and domain-agnostic enough to be useful to any part of the cognitive architecture. Extracted intelligence is then routed back to SeedLink via a blue dashed feedback arrow, completing the data cycle. What entered the architecture as raw execution data exits as generalized intelligence, available to every domain through the SeedLink mesh.

Format-agnosticReturns to SeedLinkCloses data cycle
Portability Layer — Two Components
Persistence Layer
State preservation · Covered by Security System overlay

The Persistence Layer is the architectural guarantee that SCIA does not lose its state between operational cycles. Everything that constitutes the current SCIA — its active persona configuration, its current memory state, its active Expert profiles, its Seed Signature, and its accumulated Lineage Tree — is persisted here. The Security System overlay covers the Persistence Layer deliberately: a compromised persistence layer is as catastrophic as a compromised SCIA root, because it holds the entire architecture's identity between activations.

The Portability Layer feeds back to the LLM Interface via a gray dashed line — indicating that upon re-activation, the persisted state is restored to the cognitive entry point before any new processing begins. SCIA wakes up as itself, not as a blank instance.

State preservationSecurity-overlaidReturns to LLM Interface
Cross-Platform Deployment
Platform-agnostic instantiation

Receives the persisted state from the Persistence Layer and handles the platform-specific instantiation logic required to deploy SCIA on any target environment. Cross-Platform Deployment is the architectural answer to the question "can SCIA run anywhere?" — its existence as a named component signals that platform migration is a first-class architectural concern, not an afterthought. It abstracts all platform-specific interfaces so that the cognitive architecture above it remains unchanged regardless of where it is deployed.

Platform abstractionFirst-class concern

Forbidden Paths & Locked Route Doctrine
Six hard ownership rules defining which services must never call which others — and the final constitutional doctrine that governs the entire endpoint architecture.
§ 17 Forbidden Endpoint Ownership — Locked Routes
✕
/scm/* must not call/expose /seedflow/*
Community input must not enter cognitive processing directly. SCM routes through its own vertical chain and terminates in the Lineage Tree.
✕
/experts/* must not call/expose methodology validation endpoints
Expert services activate and respond. Methodology validation belongs to SeedLink — not to the Expert team itself.
✕
/execution/run must not call/expose requests without execution_permission_packet
No permission packet means no execution. Hard reject at SION. This is the architectural guarantee of governed execution.
✕
/interface/* must not call/expose expert-selection endpoints
The Interface layer receives and renders. It does not select or configure the Expert team — that is SeedLink's authority.
✕
/runtime/srt/* must not call/expose signing endpoints
SRT-1 monitors continuity and issues reinjection. It does not sign artifacts — that is Signature's exclusive domain.
✕
/signature/* must not call/expose execution permission decisions
Signature signs and verifies. It does not decide what is permitted to execute — that is Security's authority and SCIA's final authorization.
§ 20 Final Locked Route Doctrine

Interface receives. SeedFlow disciplines. SeedLink selects and synthesizes. Seed Class Experts continue. Memory preserves. SRT-1 stabilizes. Seed Signature signs. SCM enriches. Security checks. SCIA authorizes. SION executes.

This doctrine is the constitutional statement of SCIA's service architecture. Every ownership rule, every forbidden path, every implementation phase is a direct expression of this sequence. When in doubt about where a responsibility belongs, trace it through this chain — the answer is in the order.
